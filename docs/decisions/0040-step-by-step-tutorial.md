# 0040 — Step-by-step tutorial on the live installation

- **Date:** 2026-10-31
- **Status:** accepted

## Context
When an installation is handed over, the person taking it over has to learn how the system works for their kind of organization: a language institute, a school chain or a company. The user wants a tutorial made of scenarios, one per kind of client. Each scenario is a roadmap of missions done in order («build a branch called …»). A mission ticks when it is done and the next one opens. The person switches to the role each mission needs. The tutorial runs **on the live installation**, and starting again at any point deletes the data the tutorial made.

## Options considered
- **Where it runs:** a separate training installation was proposed, but the user chose the live one. So the tutorial must keep its data apart and be able to delete it.
- **Telling a mission is done:** listening to events (fragile when the person takes another way, or deletes and makes again), or **checking the state** (chosen). Each mission asks whether the rows it needs exist among the rows made in the run.
- **Finding the tutorial's rows for deletion:** naming conventions or flags on every table (invasive), or **recording every row made in tutorial mode** (chosen).

## Decision
- Module `Tutorial`. Scenarios ([Scenario](../../Modules/Tutorial/app/Scenarios/Scenario.php)) have chapters of [Mission](../../Modules/Tutorial/app/Scenarios/Mission.php)s: steps, who does it, a link, the account to sign in with and a done check. They are registered in [Scenarios](../../Modules/Tutorial/app/Scenarios/Scenarios.php). The first scenario is [LanguageInstitute](../../Modules/Tutorial/app/Scenarios/LanguageInstitute.php), with the fewest options: a branch and a registrar by quick entry; a document type and a contract type, a hiring workflow (steps «بررسی مدارک», «مصاحبه», «تنظیم قرارداد», all for the person taking the tutorial), a job position whose form asks for the degree, an application on the public «همکاری با ما» form, the document check, the interview, the contract draft and the final approval, which hires the instructor and issues her contract; an admission workflow and program, a public preregistration, admission by the registrar, then a term, a class, members, a one-off session and the teacher's attendance (20 missions). The document and contract missions are only offered while the Document / Contract modules are on (ADR 0041); without them the workflow has the interview step only.
- **A run** (`tutorial_runs`, one per person) stores the missions done. Order is linear: only the current mission is checked ([TutorialProgress](../../Modules/Tutorial/app/Services/TutorialProgress.php)), and a mission done early ticks when its turn comes.
- **Tutorial mode** is a session key ([TutorialMode](../../Modules/Tutorial/app/Services/TutorialMode.php)). It counts only while the run's owner is signed in or impersonating, so it holds when they sign in as another account or fill a public form. While it is on, a listener on every model's `created` event writes the row into `tutorial_records` ([TutorialRecorder](../../Modules/Tutorial/app/Services/TutorialRecorder.php)).
- **Role switch:** a mission may name an account made earlier in the run. «ورود با حساب …» impersonates it through the existing impersonation ([ADR 0008](0008-impersonation.md)). Only super admins use the tutorial.
- **Auto-fill:** a mission may give `fill()` values keyed by field name. The bar's «پر کردن خودکار» button writes them into the Livewire form or the top modal open on the page (`data.*` or `mountedActions.N.data.*`), so the person only checks and saves. Both hiring and admission workflow missions supply the workflow name and subject type; their step configuration is still entered following the mission instructions. Fields the form lacks are skipped; with no form open the bar says to open one. Only the admin panel's bar has it so far; the Inertia bar (`TutorialBar.vue`) and the public forms, workflow steps, program, members, schedule and attendance don't yet.
- **Starting again** ([TutorialReset](../../Modules/Tutorial/app/Services/TutorialReset.php)) deletes the recorded rows newest first, without model events, then the role assignments and notifications of deleted users and tenants, then the run. It is all or nothing: if a row from outside the tutorial still points at one of its rows, nothing is deleted.
- **The public site hides tutorial rows from everyone but their maker.** A core hook, [HiddenRecords](../../app/PublicSite/HiddenRecords.php), is applied to the site's tenants (footer, `/{slug}`), to `/preregister`'s programs and tenants and to `/careers`' job positions, so real visitors never see «شعبه ونک» or the practice program.
- **UI:** «آموزش گام‌به‌گام» in the admin panel (scenarios, roadmap, pause / resume, «شروع دوباره»). «نمای فلوچارت» (on each scenario card and next to «شروع دوباره») opens a modal with the scenario as a swimlane chart: one column per actor (`Mission::actor()`), missions top to bottom with chapter bands, arrows to the next mission, the run's done / current / locked states, and a mark on missions done with another account. `TutorialFlowchart` works out the positions; the view draws them with HTML and an SVG overlay (no chart library). The admin panel uses a floating Livewire card with a draggable header, saved position/minimized state, progress indicator, numbered instructions and a scrollable body for small screens; its action footer stays outside the scrolling instructions so navigation and auto-fill remain visible; dragging only the header leaves instruction text selectable and touch scrolling available. The current mission, its link and role switch also appear in a top bar using `TutorialBar.vue` with the shared `tutorial` prop on Inertia pages. Both poll.

## Consequences
- Only rows made with Eloquent in a web request are recorded. Rows made by queue workers or with query-builder inserts are not, and changes to rows that existed before are not undone. Missions should therefore only create, and module code should create rows with Eloquent.
- Files uploaded in the tutorial (media) stay on disk after a reset: in the language-institute scenario, the applicant's résumé and degree.
- Everything made while the mode is on counts as tutorial data, including real work done by mistake. The bar shows the mode on every page, and it can be paused.
- Admin lists (users, tenants, access map) do show tutorial rows; only the public site hides them.
- More scenarios (school, company) reuse the engine; each needs a test that walks its missions.
